先分清，什么在变。

密钥、分组、轮密钥、输出长度，描述的是不同的事情。看到一个位数，先问它属于哪一项。

KEY LENGTH

密钥长度

秘密参数的长度。DES 用 64 位存放密钥，其中 8 位用于校验，真正参与运算的有效密钥为 56 位。密钥长度也不能跨算法直接比较安全强度。

BLOCK SIZE

分组长度

一次分组变换处理多少位。DES 一次处理 64 位，AES 和 SM4 一次处理 128 位。AES-256 的分组依然是 128 位。

ROUND KEY

轮密钥长度

主密钥通过密钥扩展生成每轮使用的参数。DES 每轮使用 48 位轮密钥，共 16 轮；这些轮密钥不意味着多出 768 位独立秘密。

OUTPUT LENGTH

输出长度

一次分组变换的输出与分组等长。整条消息的密文还可能带填充、IV 和认证标签。哈希输出是摘要长度，签名输出取决于方案与编码。

加密 → 恢复消息

持有合适密钥的人可解密。目标是保密。

哈希 → 计算摘要

没有“解密”操作。普通摘要不能证明消息来自谁。

签名 → 公钥验证

私钥签名、公钥验证。消息通常不因此被隐藏。

MAC → 共享密钥认证

双方用共享秘密检测篡改。HMAC 属于 MAC。

算法决定一次变换。

先辨认任务类型，再记关键参数。分组密码的输出块大小、流密码的消息长度、公钥算法的编码长度，不能放在同一个概念里比较。

DES

教学 / 历史算法

有效密钥 56 bit，64 bit 分组。16 轮 Feistel 网络，加解密共用结构，解密逆序使用轮密钥。

密钥
64 bit，含 8 bit 校验
轮密钥
48 bit × 16

DES 的输出块仍为 64 bit。密钥位数、轮密钥位数和分组位数是三个不同参数。

3DES / TDEA

历史兼容

对一个 64 bit 分组执行三次 DES：E_K₃(D_K₂(E_K₁(P)))。三密钥版本的 168 bit 密钥材料不等于 168 bit 安全强度。

分组 / 强度
64 bit / 约 112 bit
密钥选项
168 / 112 / 56 bit

NIST 自 2024 年起不再允许施加新的 TDEA 保护，历史数据解密等有例外。64 bit 分组也限制单密钥数据量。

AES

现代分组密码

128 bit 分组始终不变。密钥长度决定轮数，轮内使用字节代换、行移位、列混合和轮密钥加；末轮省略列混合。

密钥 / 轮数
128/192/256 bit → 10/12/14 轮
轮密钥
128 bit × 11/13/15 组

轮密钥组数包含初始 AddRoundKey。现代应用通常在经过认证的协议或 AEAD 方案中使用 AES。

IDEA

理解混合运算

128 bit 密钥，64 bit 分组；8 个完整轮与一个输出变换。混合异或、模 2¹⁶ 加法和模 (2¹⁶+1) 乘法。

轮密钥
16 bit × 52
分组 / 输出
64 bit / 64 bit

52 = 8 × 6 + 4。特殊乘法将全零 16 bit 字解释为 2¹⁶，而不是直接当作普通零相乘。

SM4

国密分组算法

128 bit 密钥与 128 bit 分组，32 轮迭代。每轮使用一个 32 bit 轮密钥；解密时逆序使用。

密钥 / 分组
128 bit / 128 bit
轮密钥
32 bit × 32

公开算法，可软硬件实现。分组长度与 AES 相同，不代表内部结构相同。

RC4

历史算法

内部维护 256 字节置换表，逐字节产生密钥流。算法本身没有独立 IV 输入，协议层拼接密钥不能消除其统计偏差。

密钥材料
1-256 B，历史常见 40/128 bit
输出
与明文等长

TLS 已禁止 RC4。原报告“40-2048 位”不是完整可变密钥范围；也不能将内部状态位数等同于安全强度。

ZUC

国密通信算法

通过线性反馈移位寄存器、比特重组和非线性函数生成密钥流。ZUC-128 用于 LTE 的 128-EEA3 与 128-EIA3。

ZUC-128
K = 128 bit；IV = 128 bit
密钥流
每次输出 32 bit 字

ZUC-256 有不同 IV 接口表示，报告列举 184 bit 版本；以所用标准或实现为准。同一 (K, IV) 不得重用。

ChaCha20 / Salsa20

现代流密码家族

以加法、循环移位和异或组织运算。ChaCha20-IETF 使用 256 bit 密钥、96 bit nonce；常与 Poly1305 组合为 AEAD。

ChaCha20-IETF
256 bit key / 96 bit nonce
输出
与明文等长

Salsa20 和原始 ChaCha 的 nonce 布局与 IETF 版不同，不能直接套用参数。

RSA

区分编码与强度

密钥长度通常指模数 n 的位数。RSA-2048 的密文或签名为 256 字节，不能直接加密任意长度文件。

典型模数
2048 / 3072 / 4096 bit
安全强度
2048 ≈ 112；3072 ≈ 128 bit

OAEP 最大输入 k − 2hLen − 2 字节；2048 bit + SHA-256 时为 190 字节。v1.5 的 k − 11 是另一种编码规则。

ECC / SM2

曲线密码

ECC 是算法家族。256 bit 椭圆曲线通常对应约 128 bit 安全强度。SM2 在指定曲线上定义签名、密钥交换与公钥加密。

SM2 私钥
256 bit
SM2 原始签名
r = 32 B；s = 32 B

r ‖ s 共 64 B，DER 编码长度不同。65 B 常指带前缀的未压缩曲线点，不是通用签名长度。SM2 C1C3C2 常见开销 97 B。

SM9

标识密码

以用户身份标识参与构造公钥，结合系统主公钥和密钥生成中心分发的用户私钥，提供签名、加密与密钥协商。

底层参数
256 bit 素域参数
系统条件
依赖主密钥与密钥生成中心

“身份即公钥”是简写，身份字符串不能脱离系统参数独立工作；参数位数不能直接等同于安全强度。

SHA-2 / SHA-3 / SM3

摘要不是密文

任意长度消息经过哈希，得到规定长度摘要。SHA-3 采用海绵结构；SM3 输出 256 bit。SHAKE 是可扩展输出函数。

SHA-256 / SM3
512 bit 消息块 → 256 bit 摘要
SHA-512
1024 bit 消息块 → 512 bit 摘要

MD5、SHA-1 的抗碰撞性已破坏。HMAC 使用密钥和哈希构造认证码，与无密钥摘要的用途不同。

沿着线，读懂工作模式。

下面沿用报告，以 DES 的 64 位分组说明结构。分组密码只是运算器，工作模式决定它收到什么、何时运行，以及输出如何参与下一块。

DES 仅用于教学。理解这些结构时，也要分开看待“保密”与“认证”：下面六种模式本身都不提供消息认证。

CTR

错误传播，不能代替认证。

CTR 与 OFB 的“仅对应位翻转”，也意味着攻击者可以有针对性地改变明文。CBC、CFB、PCBC 的错误扩散同样不能证明消息未被篡改。实际系统应使用经过分析的认证加密方案或正确的认证组合。

AES-GCM 使用适用于 128 位分组密码的计数器加密与 GHASH 认证，并纳入关联数据及长度等信息生成标签。它不是给 DES-CTR 随意加一个哈希。接收端必须验证标签，nonce 也有严格要求。

国密算法，各有分工。

“SM” 是名称家族，不是统一功能。SM2 做公钥密码，SM3 做摘要，SM4 做分组加密；ZUC 则产生密钥流。

SM1

非公开分组算法

常见公开资料列为 128 bit 密钥和分组。内部算法与轮密钥不公开，应以具体规范与产品为准。

SM2

公钥加密、签名、密钥交换

256 bit 曲线；原始签名 64 B。GB/T 32918 系列。

SM3

杂凑

512 bit 消息块，256 bit 摘要。GB/T 32905-2016。

SM4

公开分组密码

密钥与分组均为 128 bit，32 轮。GB/T 32907-2016。

SM7

面向 IC 卡等场景

公开参数资料有限，报告中的密钥与分组长度不在此作统一结论。

SM9

基于身份的密码体系

系统主密钥、主公钥与用户身份共同参与。GB/T 38635 系列。

ZUC

序列密码

ZUC-128 使用 128 bit 密钥与 IV，每次产生 32 bit 密钥字。GB/T 33133 系列。

最后一块，如何补齐？

这里演示 DES 的 8 字节分组。PKCS#7 还适用于其他分组长度：如果缺 n 字节，就补 n 个数值为 n 的字节。

13 字节明文

13 字节明文，补 3 字节：03 03 03，总长 16 字节。

00 表示示例数据字节；绿色字节是填充，不是加密结果。

00 00 00 00 00 00 00 00
00 00 00 00 00 03 03 03

整除时也要补：8 字节明文追加 08 08 08 08 08 08 08 08，得到 16 字节。解密后检查填充再移除，才能区分真实结尾与填充。

PKCS#5

填充规则与 PKCS#7 相同，原始定义针对 8 字节分组。某些接口借用这个名称支持更大分组，应查看接口约定。

ANSI X9.23

前面的填充字节置零，最后一字节记录填充长度。缺 3 字节时为 00 00 03。

ISO 10126

前面的填充字节随机，最后一字节记录长度。作为历史方案了解，不作为新设计默认。

Zero padding

补零至分组边界。如果原文也以零结尾，单靠填充无法区分，必须另有长度约定。

CFB / OFB / CTR

不需要 PKCS#7。OFB 与 CTR 的末块使用所需长度的密钥流；CFB 按选定反馈段大小及具体接口处理。

填充不是认证

攻击者可能通过不同的填充错误响应推断信息。不要让错误信息或处理时序泄露填充是否有效。

本教程依据《密码算法与工作模式调研报告》重新组织内容与图示。下列更正直接影响学习结论；原始报告保持不变。

IV、反馈方向与 PCBC 公式

CBC 与 CFB 的 IV 应不可预测，OFB 的 IV 应在同一密钥下唯一。原报告 CFB 的“唯一即可”不充分。解密图已按数据依赖重新绘制。PCBC 统一使用 F₀ = IV、Fᵢ = Pᵢ ⊕ Cᵢ，删除原文中含当前 Cᵢ 的自引用加密公式。PCBC 的误差传播不构成认证保证。

3DES 状态与安全强度

NIST 自 2024 年 1 月 1 日起撤回 SP 800-67 Rev. 2，不再允许用 TDEA 施加新的密码保护；对已经保护的数据，解密、解包和 MAC 验证仍有例外。“允许使用至 2030 年”不适用于新增加密。168 位密钥材料与约 112 位安全强度也应分开。

签名、非公开算法与参数歧义

SM2 的原始 r、s 各为 32 字节，不是 32 位；65 字节常见于未压缩点编码。非公开算法的参数仅按可确认范围陈述，尤其不把 SM7 的 128 位参数作为统一结论。IDEA 的乘法模数写作 (2¹⁶+1)。RC4 的完整字节密钥范围、CAST-128 的轮数及 Camellia 的轮数已调整。

现代应用与模式的适用范围

CTR 本身不是认证加密；GCM 也不是任意 CTR 加上普通摘要。TLS 1.3 使用认证加密套件，磁盘加密则常见 XTS 等专用模式。教程不沿用“CTR/GCM 是所有场景首选”或“PCBC 可检测整体篡改”等绝对表述。
